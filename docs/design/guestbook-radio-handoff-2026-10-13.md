> 状态：页面原型迭代中，**还没有动任何项目代码**
> 原型位置：`.tmp-guestbook-radio/`（已被 `.gitignore` 的 `.tmp-*` 忽略，不会提交）

## 1. 背景：为什么要改

首页留言板（`app/components/messages/BubbleMessageBoard.client.tsx`）夹在更新日志和钢琴问答之间。站长觉得它很丑。主要原因有三个：粉色软圆角卡片、左右交替的聊天气泡、背景里的装饰泡泡。它和下面两个组件的风格完全对不上：

- **钢琴问答**（`app/components/ui/question.tsx`）：黑白交替的整行钢琴键，点一下会弹 Tone.js 钢琴采样，答案随之淡入。
- **页脚**（`app/components/home/creative-footer.tsx`）：巨大的 `wangjiajun`，鼠标悬停时碎成 ASCII 字符，里面藏着 love、hate、rezero、miku 等私人词。

这一轮试过、被否掉的方向，都别再提：

1. 照搬 OpenAI / Claude / Cursor 的引言墙、网格、细线列表（`guestbook-samples.html`）。站长的评价是"毫无创意，不贴合个人网站"。
2. 打字机、解码墙（`guestbook-play.html` 的 A、C 页签）。站长认为不如收音机。
3. 黑色底的收音机。站长要求和页面背景 `#faf9f5` 融为一体。
4. 节目单（列出所有留言）。留言太少，没必要。

**最终选定：收音机。** 每条留言是一个电台，拖动刻度调台，台与台之间是噪声。

## 3. v4 当前的行为（以这个为准）

**外观**
- 直接放在页面背景 `#faf9f5` 上，没有底板。文字是墨色 `#141413`，只有指针、STEREO 指示灯和"待公开"标记用陶土橙 `#d97757`。唯一的黑色元素是「播出」按钮，呼应下面的钢琴黑键。
- 页面上方有巨大的 `FM 90.5`（Inter / Arial Black 900，和页脚的 wangjiajun 同一个量级），右上角是信号格和 STEREO 指示灯。

**电台**
- 数据只有线上唯一的访客留言：逸夜语「bro,认可」（站长朋友发的）。其他都是测试或虚构数据，已经删掉，**不要再加假数据**。
- 频率自动分配：按留言 id 算出一个首选频率，被占了就往两边找空位。任意两台至少相隔 1.2 MHz，在 0.45 MHz 以内开始收到信号。
- 最多 9 台在播：上限按"至少 40% 的刻度要留给噪声"算出来，只播最新的。
- 4 个隐藏电台：刻度上不标点，播的是页脚词表里的词（89.3 hope / 94.1 miku / 101.7 love / 107.3 rezero）。
- 只有 0～1 台时，隐藏左右箭头和「自动巡台」；台数变多后才出现。
- 锁定电台时弹一个钢琴音（C4～A4）。目前是 WebAudio 合成的，做进网站时换成问答区那套 Tone.js 采样。

**噪声（两台之间）**
- 噪声文本是「将我的爱弃置于此」（网站标题）加页脚完整词表（love、hate、destroy、lonely、gregorwang、code、game、vivienne、rezero、miku、remix、cloud、hope），**正面负面的词都保留**，按顺序铺满 88～108。
- 每 0.1 MHz 固定对应其中 16 个字，相邻频率错开 2 个字。同一个频率每次看到的都是同一段。
- 每秒刷新约 18 次（这是站长指定的速度，不要调慢）。
- 停在一个频率上，约 5 秒到达上限：
  - **锚点字**一个接一个定住，最多约四分之一，顺序每个频率固定。
  - **其余的字**在符号里不停闪现真身，概率从 3% 涨到 22%，**永远不会停住**。
  - 任何一帧都不是完整的句子，要靠看的人自己在脑子里拼。
- 一挪动指针就重新开始。看清得越多，沙沙声越小。

**发留言**
- 输入上限 140 字，旁边有 `0/140` 计数。
- 播出后，留言出现在程序分配的空频率上，带「待公开，这个频率现在只有你收得到」。这对应真实的业务规则：待审核的留言只有作者本人看得到。
- 留言区固定高 112px。放不下时，锁定后先停 1.2 秒，再以 26px/s 向上滚，到底停 1.6 秒后从头开始；鼠标放上去就暂停。

## 4. 还没定的问题（下一个 session 先问站长）

1. **靠近电台时的过渡。** 现在指针接近电台时，留言里的字会被符号替换（越近越少）。这和噪声的"真字在符号里闪"看起来太像，站长问过为什么要把「bro,认可」混进符号。我给了两个方向，站长还没选：
   - 改成由淡到浓，或由模糊到清晰，和噪声在视觉上彻底区分开；
   - 不要过渡，一进入电台范围就直接显示完整留言。
2. 线上真实环境下"只有 1 条留言"的体验是否满意（例如是否要更多隐藏电台）。

## 5. 做进网站时要改的地方（**页面确认之前一律不要动**）

- 前端：用收音机替换 `app/components/messages/BubbleMessageBoard.client.tsx`。保留现有的 props（`initialMessages`、`pendingMessages`、`currentUser`、`limitStatus`），以及往 `/messages` 提交的 `useFetcher` action。挂载位置在 `app/routes/_index.tsx` 的 Bubble message board 区块。
- 后端：`app/lib/messages.server.ts` 里的 `MESSAGE_CONTENT_MAX_LENGTH = 500` 要改成 120～140，同时改提交校验。每日上限 `MESSAGE_DAILY_LIMIT = 10` 不变；`MESSAGE_BOARD_LIMIT = 20` 要和"最多 9 台在播"对齐。
- 频率要在**留言创建时算一次并存进数据库**（D1 加一列），以后永不改变。原型里每次加载都重新算，只是演示。
- 未登录时，「播出」要变成去登录（`/auth?returnTo=/`），和现在的留言板一致。
- 钢琴音换成 Tone.js 的 Salamander 采样，做法参照 `question.tsx`：进入视口才加载、组件卸载时 dispose。
- 尊重 `prefers-reduced-motion`：原型里已经处理了（不闪烁、不扫台动画）。
- 移动端：原型只粗略处理过，需要认真看一遍。

## 6. 和站长协作的规矩（很重要）

- **任何改动都要先等站长确认。** 站长问"说说你的看法""是故意的吗"时，只回答，**不要改文件**。上午因为擅自改动被叫停、要求还原过一次。
- **每次迭代复制一个新版本文件**（v4 → v5），旧版本保留，方便回退。
- 原型用本地 HTML 直接在浏览器打开（`Start-Process`），不要走 Artifact。
- 改完先用 Playwright 自己测一遍（打开 `file:///...`，用 `browser_run_code_unsafe` 读状态或截图），确认没问题再交给站长。截图会落在 `.playwright-mcp/`，这个目录没有被 gitignore，测完要清理掉。
- 设计方向要"好玩、有个人性格"：一个具体的物件做隐喻，配声音，再藏一点私人彩蛋。参照钢琴问答和页脚，不要照搬大公司的做法。
- 站长说话直接，嫌慢、嫌丑会直说，按字面意思理解就好。比如上午说"太慢"指的是闪烁速度，不是坍缩速度，我理解错了一次。拿不准的时候先问。
