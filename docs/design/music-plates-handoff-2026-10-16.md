### 已知问题 / 以后要注意

- **只有中文**：图版里的文字都写在数据和 SVG 生成函数里，没走 react-intl，日文 / 英文页面看到的也是中文。要做翻译时，需要把 `music-tree.ts` 的文案和 `music-plates.ts` 里的图例文字拆出来。

- 生长动画：服务端先输出完整的树，水合后（没开「减少动态效果」时）缩回 2015 年，滚到可见区域再自动长一遍。

- 这次只跑了 `npm run typecheck`、eslint、`npm run build`、`npm test`，以及在 Node 里比对新旧生成函数的输出（节点数、标本数、地层高度一致，无 NaN）。页面没有在浏览器里逐项检查。


## 目标

把音乐子页（`app/routes/($lang).music.tsx` → `app/components/music/MusicPageClient.client.tsx`）从「深色星空 + 粒子 + GSAP 满屏动效 + 大红大紫背景」改成米色纸面的科学图版风格。灵感来自一张 Nature 蝴蝶系统发育树。旧页面上的内容一样都不能丢：时间线、年度歌手、最爱歌词、年度关键词、常听专辑、下午听歌和统计。

预览文件：`docs/design/music-phylogeny-preview-2026-10-16.html`。它是单文件 HTML，数据写在文件里，直接用浏览器打开即可。

## 已确认的数据和规则

- **年度歌手：** 2015–2018 Mili，2019–2020 FELT，2021 和 2022 Vivienne，2023 四季音色，2024 和 2025 Vivienne。2026 年还没出。
- **四季音色 = 纯音乐。**
- **分类规则（用户指出之前的分类逻辑有问题之后定的）：** 每一层只按一个标准分。
  - 科 = 风格：流行 / 电子 / 古风 / 纯音乐。每位歌手只归一个科。
  - 属 = 歌手，种 = 歌。
  - 语种和来源（动画 · VN / 游戏 / 影视 / 同人 · 翻唱，原创不标）按每首歌标在外圈两道细环上。
  - 之前的错误是把语种（华语 / J-POP / K-POP）、来源（动画 / 游戏）、圈子（东方同人）、风格（电子）混在同一层。
  - **还没确认：** 这四个风格分得对不对，比如 Key 社和 ClariS 要不要单列「二次元」。
- **地层岩性 = 组**：每位年度歌手连续的年份算一个组，各用一种岩石。Mili 是片岩，FELT 是石灰岩，Vivienne 是砂岩，四季音色是页岩。
- **动效原则：** 有意义的可以做，比如谱系树随时间生长、地层一层层沉积下来。不要循环播放的装饰性动效，并且要尊重系统的「减少动态效果」设置。
- **数据：** 用户以后会给更完整的数据，但这是长期的事。实现时所有内容都要由数据文件驱动，以后直接替换数据即可。

## 验证方式

用户不希望用 Playwright 逐页检查。之前的做法是：
- 把预览 HTML 里的 `<script>` 抽出来，在 Node 里跑 `globalThis.__phylo` 暴露的纯函数（`build` / `toSvg` / `strataSvg` 等），检查输出里有没有 NaN。
- 用项目里的 `sharp` 把 SVG 渲染成 PNG 看排版。sharp 不支持 `textPath`，也加载不了远程图片，所以弧形文字和封面只能在浏览器里确认。
- 交互逻辑用 `linkedom` 在无头 DOM 里模拟（装在 scratchpad 里，没进项目依赖）。
