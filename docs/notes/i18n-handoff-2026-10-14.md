> 下一阶段（经验教训、自动识别语言）见 `docs/notes/i18n-lessons-and-next-steps-2026-10-15.md`。

> 2026-10-15 更新：❌ 项已全部迁完并提交；词典日 / 英 489/489；tsc、测试、build 通过。浏览器逐页检查由站长手动做。`build/client` 偶发 EBUSY（某个子目录句柄被占，文件本身没锁）：把目录改名挪开再 build 即可。

## 已定的方案（不要再改）

- react-intl + `@formatjs/unplugin/vite`：代码里只写 `defaultMessage` 中文原文，构建时注入 6 位哈希 ID（和 OpenAI 一样）。
- URL：中文无前缀，`/ja`、`/en` 前缀；页面路由都在 `app/routes/($lang).*`；`/zh/*` 301 去前缀，非法前缀 404。
- root loader 按语言下发整本词典；`<html lang>`、hreflang（只对 `TRANSLATED_PATHS` 输出）在 `root.tsx`。
- 站内链接一律用 `~/components/common/LocaleLink` 的 `Link`（自动带前缀）。
- 语言选择器在 Header（页脚是站长自己的安排，别动）。
- **cookie 记忆和浏览器语言识别放到最后做**，做法照 OpenAI：不强制跳转，只记首选语言（见 `docs/reference/openai-site-teardown-2026-10-13.md` 第 4 节）。

## 两类文案的放法

1. **界面文案 → 词典**：`<FormattedMessage defaultMessage="…" />` / `intl.formatMessage({ defaultMessage: "…" })`；loader 里用 `getServerIntl(getRouteLocale(params))`；meta 里用 `getMetaIntl(matches)`。
2. **长内容 → 覆盖层**（`app/lib/localized-content.ts` 的 `localized` / `localizedById`）：中文原文留在 `app/data`，日 / 英只写要翻的字段，缺的回落中文。已有：`app/components/home/cyber-terminal-content.ts`、`app/data/i18n/game.ts`。

## 翻译分工

批量翻译（词典 JSON、更新日志覆盖层、各页覆盖层）交给 **Haiku 子代理**：给它 `npm run i18n:check` 的缺失列表或中文数据，让它按 id 输出 JSON，主模型只抽查语气和占位符。

## 踩过的坑

- react-intl 12：`defineMessages` 里带 `{占位符}` 的消息传 values 会类型报错 → 带占位符的消息直接内联写 `defaultMessage`，或用 `defineMessage<{ x: string }>()`。
- `DEFAULT_LOCALE` 必须是字面量 `"zh"`（`satisfies Locale`），否则 `TranslatedLocale` 收窄失效。
- 富文本消息用标签：`"…<link>文字</link>…"` + `values={{ link: (chunks) => … }}`。
- 不要按中文名查表（游戏大图曾按中文名查，翻译后失效）；颜色等按顺序 / id 取。
- 开发时如果 3000 端口被旧 dev server 占着，新插件不生效，会报 `ID is required`。
